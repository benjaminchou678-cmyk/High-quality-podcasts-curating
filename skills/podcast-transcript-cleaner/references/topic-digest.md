# 议题提要规范

## 定位

“议题提要”是完整逐字稿之前的快速阅读层，不替代、不删减下方按时间排序的完整逐字稿。

- 最多两层：顶层议题 + 二级事实要点。
- 默认 3–8 个顶层议题；每个议题 1–6 个二级要点。
- 每条都必须附可核验的逐字稿时间范围。
- 不生成金句、结论、建议或脱离原话的分析。

## 顶层 bullet

```markdown
- **议题名称**（00:03:12–00:18:40）：对核心内容的忠实概括。
```

议题名直接使用对话讨论的问题或对象，不用“其他”“补充”等空泛标题。概括保留关键判断与限定，不只写关键词。

## 二级 bullet

```markdown
  - 具体事实、原因、对比、案例或不确定性。（00:05:20–00:07:05）
```

优先保留：数字、金额、年份、比例、人数、版本号、案例、类比、反例、人名、公司名、产品名、英文缩写、专业术语、反方观点和不确定性。

二级要点应是信息密度较高的完整意群，不拆成短词条；不得出现第三层嵌套。

## 忠实度

- `议题提要` 的顶层与二级 bullet 默认全部使用中文；英文访谈也不另建英文 bullet。
- 人名、公司名、产品名、论文名、代码标识和专业术语可保留英文，并在首次出现时给出中文解释。
- 只用逐字稿与用户材料中有直接证据的内容。
- Shownotes 可帮助识别章节时间和术语，但不能作为发言事实直接写入提要。
- 不纠正事实、不补外部背景、不推断身份、不强化观点。
- 保留否定、程度、条件、“可能”“不好判断”“尚未验证”等限定。
- 敏感或负面表述写成“发言中提到/认为/判断”，不转成编辑者确认的事实。

## `topic-digest.json`

```json
{
  "version": "1.0",
  "source": "transcript",
  "items": [
    {
      "topic": "产品定位与使用场景",
      "summary": "产品定位为 AI 养老机器人，核心是提供移动能力和持续数据采集能力。",
      "start_time": 12.0,
      "end_time": 325.0,
      "points": [
        {
          "text": "熟悉场景约占 90%，陌生场景约占 10%；熟悉地点可先驾驶到现场完成标注。",
          "start_time": 88.0,
          "end_time": 132.0
        }
      ]
    }
  ]
}
```

规则：`version` 固定为 `1.0`，`source` 固定为 `transcript`；所有时间位于逐字稿范围内；`end_time >= start_time`；`points` 不再嵌套。

## 生成和验证

1. 完整阅读逐字稿后再归纳议题。
2. 将相邻、同义内容归组；不连续或语义不同的内容拆开。
3. 为每个议题和要点填写时间证据；没有可靠时间证据就不写。
4. 输出 `topic-digest.json`，由清洗脚本渲染。
5. 逐条对照原文，确认未新增事实、改变立场或漏掉关键限定。

文档顺序：标题与声明 → 元信息 → `## 议题提要` → `## 逐字稿` → 阶段标题与完整对话。

脚本在 `topic-digest.json` 缺失时保持向后兼容并省略提要；新版正式产出应生成该文件。信息不足或高风险时允许少列议题，不得凑数。
