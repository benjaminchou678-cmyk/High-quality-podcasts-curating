# ASR 与飞书集成说明

## 什么是 ASR 通道

ASR（Automatic Speech Recognition，自动语音识别）通道，是“从音频得到结构化转写结果”的实际执行能力。它可以是：

- Agent 平台自带的音频转写工具；
- 云厂商语音识别 API；
- 本地 Whisper / faster-whisper 等模型；
- 能把音视频上传并返回逐字稿的会议或妙记产品。

Skill 本身是工作流与规范，不是语音识别模型。把 Skill 复制给另一个 Agent，并不会自动复制原环境的 ASR 工具、账号、额度或权限。

## 一般 Agent 是否具有

没有统一答案：

- **纯文本 Agent**：通常不能直接读取长音频。
- **支持音频附件的多模态 Agent**：可能能理解或概括音频，但未必能稳定导出逐句时间戳。
- **带专用音频工具的 Agent**：更可能提供时间戳、置信度和说话人分区（speaker diarization）字段。
- **企业 Agent 环境**：能力由管理员安装的工具、权限和额度决定。

因此不能用“Agent 能听音频”推断它满足本项目的完整 ASR 契约。

## 本项目期望的最小输出

```json
[
  {
    "start_time": 0.0,
    "end_time": 4.2,
    "text": "欢迎收听本期节目。"
  }
]
```

推荐输出：

```json
[
  {
    "start_time": 0.0,
    "end_time": 4.2,
    "speaker": "1",
    "text": "欢迎收听本期节目。",
    "confidence": 0.97
  }
]
```

字段说明：

- `start_time` / `end_time`：秒，必须单调递增。
- `text`：对应时间段文本。
- `speaker`：可选，但说话人分区需要它或等效信息。
- `confidence`：可选，范围通常为 0–1；没有就省略，不用 0 冒充。

## 能力测试清单

让同事对 1–2 分钟多人对话样本执行转写，然后确认：

1. 能否处理目标音频格式或公开音频 URL；
2. 是否返回完整正文；
3. 是否包含逐句起止时间；
4. 是否包含 confidence；
5. 是否区分两位以上说话人；
6. 长音频是否有限额、超时或异步任务要求；
7. 结果能否导出为 JSON 或稳定转换为 `segments.raw.json`。

## 能力降级

### 没有 ASR

仍可完成 RSS 采集和已有公开逐字稿清洗。没有公开逐字稿的单集标记为 `asr_required` 或 `unavailable`，不得从 Shownotes 拼出正文。

### 有 ASR、没有 speaker

继续生成逐字稿，将 speaker 标为未确定，并把 `speaker_missing` 计入质量风险。不要猜测身份或强行交替标注。

### 有 speaker、没有 confidence

继续生成，置信度指标写 `null`，增加 `confidence_unavailable` 风险。

### 只有整段文本、没有时间戳

不伪造时间戳。可以保留原始全文，但不应声称符合本项目的带时间戳逐字稿标准；建议更换转写通道。

## 飞书输出所需能力

飞书输出与 ASR 相互独立，需要：

- Agent 环境具有飞书在线文档创建/编辑工具；
- 当前用户已登录并授权；
- 对目标文件夹和已有文档具有写权限；
- Skill 执行时用户选择了 `lark_doc` 或“两者都要”。

没有飞书能力时选择 Markdown 输出即可。Markdown 清洗和本地归档不依赖飞书。

## 安全建议

- 不把飞书 token、API key、cookie 或账号凭据写入 GitHub。
- 使用云 ASR 前确认音频内容是否允许发送到该服务。
- 遵守播客来源条款、版权要求、企业数据政策及相关隐私规则。
- 日志中不要保留临时下载票据、认证头或完整请求凭据。
